Validation Rules

All rules enforced by openalex validate — with examples of passing and failing inputs.

✅ Run validation before every collection uv run openalex validate --no-api takes under a second and can save you from a failed 820 MB download.

Keyword validation (6 rules)

Applied to the full contents of keywords.txt. All rules must pass or the command exits with code 1.

  • R1
    Non-empty

    The file must contain at least one non-whitespace character.

    ✅ ("quantum computing" OR "qubit")
    ❌ (empty file)

  • R2
    Balanced parentheses

    Every opening ( must have a matching closing ). The count of ( must equal the count of ).

    ✅ ("quantum computing" OR ("qubit" AND "gate"))
    ❌ ("quantum computing" OR ("qubit" AND "gate") — missing one )

  • R3
    Even double quotes

    The total number of " characters must be even — every opening quote must have a closing quote.

    ✅ ("quantum computing" OR "qubit")
    ❌ ("quantum computing OR "qubit") — 3 quotes (odd)

  • R4
    Uppercase operators

    Boolean operators must be uppercase: OR, AND, NOT. Lowercase versions (or, and, not) are treated as literal search terms by OpenAlex, which silently breaks your query.

    ✅ ("quantum computing" OR "qubit")
    ❌ ("quantum computing" or "qubit")

    ⚠️ Silent failure OpenAlex does not error on lowercase operators — it just treats them as search terms. This rule catches a mistake that would otherwise inflate your result count silently.
  • R5
    No adjacent operators

    Two operators in a row (e.g. OR OR, AND NOT NOT) indicate a copy-paste error or missing term.

    ✅ ("qubit" OR "qutrit" OR "qudit")
    ❌ ("qubit" OR OR "qutrit")

  • R6
    No empty groups

    An empty parentheses pair () is not valid and usually results from an incomplete edit.

    ✅ ("quantum computing" OR "qubit")
    ❌ ("quantum computing" OR ())

Topic ID validation (2 stages)

Applied to every non-comment line in topics.txt.

  • S1
    Format check — T + exactly 5 digits

    Every topic ID must match the regular expression ^T\d{5}$: the letter T followed by exactly five digits, nothing else.

    ✅ T10020, T11414, T12537
    ❌ t10020 — lowercase t
    ❌ T1002 — only 4 digits
    ❌ T100200 — 6 digits
    ❌ "T10020" — quoted (Python list format pasted by mistake)

    This stage runs instantly with no internet connection. Malformed IDs are reported and the valid ones continue to Stage 2.

  • S2
    API existence check

    All valid-format IDs are checked against the OpenAlex API in parallel: GET https://api.openalex.org/topics/{id}. A HTTP 200 means the topic exists; anything else (404, timeout) means it doesn't.

    ✅ T10020 → HTTP 200 — confirmed
    ❌ T99999 → HTTP 404 — not found on OpenAlex

    This check runs all IDs concurrently — even 137 IDs complete in under 3 seconds.

    ℹ️ Skip with --no-api If you don't have internet access or just want a quick syntax check, use openalex validate --no-api to skip Stage 2 entirely.

Using validate in scripts

openalex validate exits with code 1 on any failure, making it safe to use in shell scripts or CI:

#!/bin/bash
set -e

uv run openalex validate --no-api || { echo "Fix validation errors first"; exit 1; }
uv run openalex download
uv run openalex convert-to-db

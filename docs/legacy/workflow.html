End-to-End Workflow

From blank config to a fully loaded DuckDB database — step by step.

ℹ️ Context This pipeline collects quantum computing papers published 2003–2024 using a two-layer filter: a Boolean keyword query applied to titles and abstracts, plus a set of OpenAlex topic IDs. The result is ~96,000 papers stored in a normalised DuckDB database.

Overview

The pipeline has three phases:

  • Explore (steps 1–5) — understand what's in OpenAlex before downloading anything
  • Validate (steps 6–7) — confirm your query returns relevant papers via a random sample
  • Collect (steps 8–10) — download everything and build the database

Explore Phase

  1. Initialise config files

    Creates config/collection.yml, keywords.txt, and topics.txt with templates.

    uv run openalex init

    Then edit collection.yml to add your API key and email.

  2. Validate your input files

    Checks keyword syntax (6 rules) and topic ID format before hitting the API. Catches mistakes like unbalanced parentheses or lowercase operators.

    uv run openalex validate --no-api   # syntax only, no internet needed
uv run openalex validate            # + verify each topic ID exists on OpenAlex

  3. Test the keyword search count

    Fires a single lightweight API request. No data downloaded — just a count. Lets you tune your query before committing to a download.

    uv run openalex search

    Expected output for the default quantum computing query: ~96,000 papers.

  4. Discover which topics appear

    Uses the OpenAlex group_by API to list all research topics that appear in your keyword results, sorted by paper count.

    uv run openalex get-topics                  # top 20 topics (terminal)
uv run openalex get-topics --details --csv  # all topics + counts → CSV file

    Use the CSV to decide which topic IDs to include in topics.txt.

  5. Test the filtered count

    Apply both keyword and topic filters together to see the final dataset size before downloading.

    uv run openalex search-filtered

    This should be close to (or slightly above) the keyword-only count if your topics are well-chosen.

Validate Phase

  1. Take a random validation sample

    Uses reservoir sampling — every paper in the result set has an equal probability of being selected, regardless of its position. A sample of 385 gives a ±5% confidence interval at 95% confidence. 

    uv run openalex sample --size 385

    The command shows a table of sampled papers and offers to save them to CSV. Review the titles manually — if you see many irrelevant papers, tighten your keyword query.

    💡 Rule of thumb If >10% of your sample looks irrelevant, refine the query and re-sample. Don't download 820 MB of noise.

Collect Phase

  1. Download all papers to JSONL

    Downloads every matching paper using 10 async concurrent streams. Papers are written to a .jsonl file (one JSON object per line) with a 1,000-record write buffer to minimise I/O. 

    uv run openalex download

    You'll be shown a pre-flight summary (estimated total + disk space needed) and asked to confirm before anything is written. The download for ~96k papers takes approximately 15–30 minutes and produces a file around 820 MB.

    ⚠️ Do not interrupt If the download is interrupted, re-running the command will overwrite the partial file. Resume support is not yet implemented.

  2. Convert JSONL to DuckDB

    Reads the JSONL line by line and populates the 5-table normalised schema. Handles deduplication, abstract reconstruction, and auto-creates missing country records. 

    uv run openalex convert-to-db

    You'll be prompted for the input JSONL path and output database name. Takes approximately 4–6 minutes for 96k papers.

    Output tables:

    TableContents~Rows (96k papers)
    papersCore metadata per publication96,665
    authorsResearcher names + ORCIDs100,767
    institutionsOrganisations + country codes7,686
    countriesCountry reference table217
    contributionsPaper ↔ author ↔ institution links405,562

  3. Check database completeness

    Runs a set of completeness queries and displays a health report with Tier 1/2/3 classification.

    uv run openalex check-db
    TierMeaningTypical %
    Tier 1Complete — has both country and institution~79%
    Tier 2Partial — missing country or institution~21%
    Tier 3Ghost — no authorship data at all<1%

Full pipeline in one block

# Setup (one time)
uv run openalex init
# → edit config/collection.yml, add API key + email
# → edit config/topics.txt, add topic IDs one per line

# Explore
uv run openalex validate --no-api
uv run openalex search
uv run openalex get-topics --details --csv
uv run openalex search-filtered

# Validate
uv run openalex sample --size 385

# Collect
uv run openalex download
uv run openalex convert-to-db
uv run openalex check-db

How It Works

Deep dive into the architecture, algorithms, and implementation details.

System Architecture

The OpenAlex CLI is built as a modular Python package with clear separation of concerns:

🎯

CLI Layer (click)

Command definitions with type-safe options and help text. Each command is a pure function that reads config and executes a specific task.

🔌

API Client (aiohttp)

Async HTTP client with retry/backoff logic, rate limit handling (HTTP 429), and cursor-based pagination for large result sets.

⚙️

Config System (PyYAML)

YAML-based configuration with validation. Config files are not tracked in git to protect API keys and allow local customization.

🗄️

Data Layer (DuckDB + Polars)

Fast JSONL processing with Polars, loaded into normalized DuckDB tables for analytical queries.

Core Components

1. AsyncOpenAlexClient

The API client handles all communication with OpenAlex. Key features:

  • Cursor-based pagination: Uses opaque cursor tokens instead of page numbers for reliable iteration through large result sets
  • Exponential backoff: Retries failed requests with delays: 2s → 4s → 8s → 16s → 32s
  • Concurrent requests: Up to 10 parallel requests with semaphore-based rate limiting
  • Buffered writes: JSONL writer buffers 1000 records before flushing to disk (reduces I/O)
async with AsyncOpenAlexClient(
    api_key=cfg.api_key,
    email=cfg.email,
    per_page=200,
    max_retries=5,
    concurrent_requests=10,
) as client:
    cursor = "*"
    while cursor:
        data = await client.fetch_page(api_filter, cursor)
        # Process results...
        cursor = data["meta"].get("next_cursor")

2. Filter Builder

Constructs OpenAlex API filter strings from configuration:

# Input
keywords = '("quantum computing" OR "qubit")'
topics = ["T10020", "T10682"]
date_from = "2003-01-01"
date_to = "2024-12-31"
doc_types = ["article", "review"]

# Output filter string
"title_and_abstract.search:(\"quantum computing\" OR \"qubit\"),
primary_topic.id:T10020|T10682,
from_publication_date:2003-01-01,
to_publication_date:2024-12-31,
type:article|review"

Filters are comma-separated. Each filter type has a specific prefix recognized by the OpenAlex API.

3. Keyword Validator

Six syntax rules prevent malformed queries from reaching the API:

  1. 1
    Non-empty query

    Rejects empty or whitespace-only keywords

  2. 2
    Balanced parentheses

    Counts open vs close parentheses

  3. 3
    Even double quotes

    Every opening quote must have a closing quote

  4. 4
    Uppercase operators

    OR, AND, NOT must be uppercase (lowercase is invalid)

  5. 5
    No adjacent operators

    Flags "OR OR", "AND AND", "NOT NOT" (but allows "AND NOT", "OR NOT")

  6. 6
    No empty parentheses

    Rejects "()" which causes API errors

4. Topic Enrichment

When you run openalex get-topics --details --csv, the tool:

  1. Fetches topic groups via group_by=primary_topic.id (returns topic ID + paper count)
  2. For each topic, fetches full metadata from /topics/{id} endpoint in parallel
  3. Extracts: display_name, description, keywords, domain, field, subfield
  4. Exports to CSV with 9 columns

Uses cursor pagination to fetch all topics (not just first 200).

5. Random Sampling

Uses OpenAlex's built-in sample parameter instead of custom reservoir sampling:

# API request
GET /works?filter=...&sample=100&seed=42&per-page=100

# Returns 100 random papers from all matching results
# No need to scan entire result set!

Benefits:

  • Instant sampling (no full scan required)
  • Reproducible with seed parameter
  • True random selection (uniform distribution)
  • Max 10,000 samples per request (API limit)

6. Abstract Reconstruction

OpenAlex stores abstracts as inverted indices to save space:

# OpenAlex format
{
  "quantum": [0, 5],
  "computing": [1],
  "uses": [2],
  "qubits": [3, 6],
  "for": [4]
}

# Reconstructed text
"quantum computing uses qubits for quantum computation"

The reconstruct_abstract() function:

  1. Flattens the index: [(0, "quantum"), (1, "computing"), (2, "uses"), ...]
  2. Sorts by position
  3. Joins words in order

Data Flow

  1. Configuration Loading

    load_config() reads config/collection.yml, validates API key presence, and provides lazy-loaded access to keywords/topics files.

  2. Filter Construction

    build_filter() combines keywords, topics, dates, and document types into a single comma-separated filter string.

  3. API Request

    fetch_page() sends HTTP GET with filter, cursor, and select parameters. Handles retries and rate limits.

  4. Response Processing

    JSON responses are parsed and written to JSONL buffer. Each line is one paper's metadata.

  5. Database Loading

    Polars reads JSONL, normalizes nested structures (authors, institutions), and inserts into DuckDB tables.

Database Schema

Error Handling

The CLI handles errors gracefully at multiple levels:

Config Errors

  • Missing config file → Exit with message to run openalex init
  • Missing API key → Exit with instructions to edit config
  • Invalid keywords → Show validation errors with line numbers

API Errors

  • HTTP 429 (rate limit) → Exponential backoff retry
  • HTTP 403 (forbidden) → Exit with "API key rejected" message
  • HTTP 500 (server error) → Retry up to 5 times
  • Timeout → Retry with longer delay

Data Errors

  • Missing abstract → Empty string (not null)
  • Missing topic → "Unknown" placeholder
  • Duplicate authors → Deduplicated by ID

Performance Optimizations

  • Async I/O: All HTTP requests and file writes are non-blocking
  • Concurrent requests: 10 parallel API calls (configurable)
  • Buffered writes: 1000-record batches reduce disk I/O
  • Polars for ETL: Rust-based DataFrame library (10x faster than pandas)
  • DuckDB: Columnar storage for fast analytical queries
  • Cursor pagination: No offset-based pagination (avoids slow deep pages)

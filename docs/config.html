Configuration

All three config files — format, fields, and gotchas.

collection.yml

The main configuration file. Generated by openalex init, located at config/collection.yml.

config/collection.yml — full annotated template 
api:
  key: "YOUR_API_KEY_HERE"        # REQUIRED — get from https://openalex.org/account
  email: "your@email.com"         # REQUIRED — for OpenAlex polite pool (faster responses)
  base_url: "https://api.openalex.org/works"  # do not change

filters:
  date_from: "2003-01-01"         # earliest publication date (ISO 8601)
  date_to: "2024-12-31"           # latest publication date
  doc_types:                      # OpenAlex work types to include
    - article
    - review
    - proceedings-article

keywords_file: "config/keywords.txt"   # relative or absolute path
topics_file: "config/topics.txt"       # relative or absolute path (optional)

collection:
  batch_size_topics: 10           # topic IDs per API filter batch
  per_page: 200                   # records per page (max allowed by OpenAlex: 200)
  concurrent_requests: 10         # parallel async HTTP streams
  max_retries: 5                  # retries on timeout or rate-limit
  retry_delay: 2                  # seconds between retries (doubles on each attempt)

output:
  jsonl_dir: "data/raw/"          # where downloaded JSONL files are saved
  db_dir: "data/db/"              # where DuckDB files are saved

api section

FieldRequiredDescription
api.keyRequiredYour OpenAlex API key. The CLI refuses to run any command if this is missing or still set to YOUR_API_KEY_HERE.
api.emailRequiredYour email address. Sent as the User-Agent header. Required for access to the polite pool (faster, higher rate limits).
api.base_urlOptionalOpenAlex works endpoint. Don't change unless OpenAlex changes their API URL.

filters section

FieldDefaultDescription
date_from2003-01-01ISO 8601 date. Papers before this date are excluded.
date_to2024-12-31ISO 8601 date. Papers after this date are excluded.
doc_typesarticle, review, proceedings-articleOpenAlex work types. Other valid types: preprint, book-chapter, dataset.

collection section

FieldDefaultDescription
batch_size_topics10How many topic IDs to include in a single API filter string. OpenAlex supports up to ~50 but 10 is safer for URL length limits.
per_page200Records per API page. 200 is the maximum allowed by OpenAlex. Don't increase.
concurrent_requests10Number of parallel async HTTP streams during download. Increase to 20 with a paid API key; decrease to 5 if you see timeouts.
max_retries5Retries per page on HTTP 429 (rate limit) or timeout. Uses exponential backoff.
retry_delay2Base delay in seconds between retries. Actual delay = retry_delay × 2^attempt.
⚠️ API key security Never commit config/collection.yml with a real API key to a public repository. Add config/collection.yml to your .gitignore, or use an environment variable and reference it in the YAML as key: "${OPENALEX_API_KEY}".

keywords.txt

Contains your Boolean search query as a single string. The entire file contents are passed to OpenAlex as the title_and_abstract.search filter.

config/keywords.txt 
(
  ("quantum computing" OR "quantum computation" OR "quantum processor" OR
   "quantum information processing" OR "quantum supremacy" OR "quantum advantage") OR

  ("quantum algorithm" OR "quantum circuit" OR "quantum gate" OR
   "quantum error correction" OR "fault-tolerant quantum computing") OR

  ("qubit" OR "qutrit" OR "qudit") OR

  ("transmon" OR "fluxonium" OR "trapped ion" OR "ion trap" OR
   "quantum annealing" OR "quantum annealer") OR

  ("Shor algorithm" OR "Grover algorithm" OR "quantum Fourier transform" OR
   "variational quantum eigensolver" OR "VQE" OR "QAOA" OR "quantum machine learning")
)

Keyword rules

  • Use double quotes around multi-word phrases: "quantum computing"
  • Use uppercase operators: OR, AND, NOT
  • Wrap the whole query in outer parentheses
  • Multiline is fine — the whole file is treated as one string
  • Lines starting with # are NOT stripped — comments will break the query

Run openalex validate --no-api to check your query syntax against all 6 rules before hitting the API. See Validation Rules for the full list.

topics.txt

One OpenAlex topic ID per line. Lines starting with # are treated as comments and ignored. The file is optional — commands with --no-topics flag will skip it.

config/topics.txt 
# Quantum computing topic IDs
# Format: T followed by exactly 5 digits

# CORE
T10020
T10682
T10382

# HARDWARE
T10478
T10022
T10037

Finding topic IDs

The easiest way is to run openalex get-topics --details --csv after setting up your keywords. This gives you a CSV of every topic ID that appears in your keyword results, sorted by paper count. Pick the ones that are relevant to your research domain.

ℹ️ Format: T + exactly 5 digits Every topic ID must match the pattern T\d{5} — the letter T followed by exactly five digits. Examples: T10020, T11414, T12537. The validate command checks this format automatically.
